# column-seal

[![CI](https://github.com/frameprivacy/column-seal/actions/workflows/ci.yml/badge.svg)](https://github.com/frameprivacy/column-seal/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**Encrypt database columns in Node.js with versioned AES-256-GCM envelopes, painless key rotation, and HMAC blind indexes for lookups.**

Zero runtime dependencies. Built on `node:crypto`. Under 400 lines of TypeScript, comments included.

## Why this exists

Every app that stores sensitive fields (emails, phone numbers, addresses, tokens) ends up rewriting the same fragile
code around `createCipheriv`:

- Where do the IV and auth tag go? Which key wrote this row, and what happens when you rotate?
- How do you stop a ciphertext copied from one user's row from decrypting fine in another user's row?
- Once the column is encrypted, how do you still answer "is this email already registered?"

`column-seal` answers those once, in a small, boring, well-tested module you can drop in and stop thinking about:

- **Self-describing envelopes.** Every ciphertext carries its format and key version, so any row can be decrypted
  without knowing which key wrote it.
- **AAD binding.** Ciphertexts are bound to `"<table>.<column>:<owner>"`. Move one somewhere else and it fails to
  decrypt instead of leaking.
- **Multi-key keyrings.** Add a key, flip the active version, re-encrypt in the background with `needsRotation` /
  `rotate`. Old rows keep working the whole time.
- **Blind indexes.** Keyed HMAC-SHA256 lookup hashes (with a separate keyring) for equality search and dedupe on
  encrypted values, plus helpers to normalize and mask common identifiers.

**Keys are never in this repository and never generated by it.** You supply them (environment, KMS-unwrapped data
key, secret manager) when you build the keyring.

## Install

```sh
npm install column-seal
```

Requires Node.js 22 or newer. ESM only.

## Usage

```ts
import { aad, createKeyring, createSeal, lookupKey, maskIdentifier, normalizeIdentifier } from "column-seal";

// Keys come from your environment or KMS as base64-encoded 32-byte values.
const seal = createSeal({
  encryption: createKeyring({ keys: { 1: process.env.ENC_KEY_1!, 2: process.env.ENC_KEY_2! }, active: 2 }),
  hmac: createKeyring({ keys: { 1: process.env.HMAC_KEY_1! }, active: 1 }),
});

// Write
const email = normalizeIdentifier("email", "  Ada.Lovelace@Example.com ");
const row = {
  email_enc: seal.encrypt(email, aad("contacts", "email", userId)), // bytea
  email_hash: seal.lookupHash("contacts:email", lookupKey("email", email)), // bytea, unique index
  email_hint: maskIdentifier("email", email), // "a•••@example.com", safe to show
  enc_key_version: seal.activeKeyVersion, // integer, indexed: drives rotation
};

// Read
const plain = seal.decrypt(row.email_enc, aad("contacts", "email", userId));

// Find without decrypting anything
// SELECT * FROM contacts WHERE email_hash = $1
const hash = seal.lookupHash("contacts:email", lookupKey("email", normalizeIdentifier("email", input)));
```

### Reading keys from environment variables

```ts
import { parseKeyring } from "column-seal";

// APP_ENC_KEYS="1:<base64>,2:<base64>"  APP_ENC_ACTIVE_KEY="2"
const encryption = parseKeyring(process.env.APP_ENC_KEYS, process.env.APP_ENC_ACTIVE_KEY, "APP_ENC_KEYS");
```

Errors name the setting (`APP_ENC_KEYS: key 2 must be 32 bytes`) and never echo key material.

Generate a key with `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`.

### Rotating keys

1. Add the new key to the keyring and make it active. New writes use it; old rows still decrypt.
2. Re-encrypt in the background, in batches:

```ts
// SELECT id, owner_id, secret_enc FROM things WHERE enc_key_version < $1 LIMIT 500
for (const r of rows) {
  const ctx = aad("things", "secret", r.owner_id);
  await db.update(r.id, { secret_enc: seal.rotate(r.secret_enc, ctx), enc_key_version: seal.activeKeyVersion });
}
```

3. When no rows reference the old version, remove it from the keyring.

Rotating the **HMAC** key is the same idea: while old hashes still exist, look up with every version and backfill.

```ts
// SELECT * FROM contacts WHERE email_hash = ANY($1)
const candidates = seal.lookupHashes("contacts:email", key); // active version first
```

## API

### Keyrings

| Function                                 | Description                                                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `createKeyring({ keys, active, name? })` | Validates and freezes a keyring. `keys` is an object or `Map` of version (1–65535) to base64 string or bytes; each must be 32 bytes. |
| `parseKeyring(list, active, name?)`      | Parses `"1:<base64>,2:<base64>"` plus an active version string, e.g. from `process.env`.                                             |

### `createSeal({ encryption, hmac? })` → `Seal`

| Member                                                   | Description                                                                  |
| -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `encrypt(plaintext, aad)`                                | String (UTF-8) or bytes → `Buffer` envelope, using the active key.           |
| `decrypt(envelope, aad)`                                 | Envelope → string. Throws on unknown key, wrong AAD, or any tampering.       |
| `decryptBytes(envelope, aad)`                            | Envelope → `Buffer`.                                                         |
| `encryptJson(value, aad)` / `decryptJson(envelope, aad)` | JSON helpers. `decryptJson` returns `unknown`; validate it at the call site. |
| `needsRotation(envelope)`                                | `true` if written with a non-active key.                                     |
| `rotate(envelope, aad)`                                  | Re-encrypts with the active key (no-op copy if already current).             |
| `lookupHash(domain, value, version?)`                    | HMAC-SHA256 of `domain NUL value`. Deterministic per key and domain.         |
| `lookupHashes(domain, value)`                            | The hash under every loaded HMAC key, active first.                          |
| `activeKeyVersion` / `activeHmacVersion`                 | Versions new writes use.                                                     |

### Helpers

| Function                                                  | Description                                                                                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `aad(table, column, owner)`                               | `"<table>.<column>:<owner>"`.                                                                                                               |
| `keyVersionOf(envelope)`                                  | Reads the key version from the header without decrypting.                                                                                   |
| `normalizeIdentifier(kind, raw, options?)`                | Canonical form for `email`, `phone`, `username`, `domain`, `name`, `address`, `birthdate`. Override `phone` / `domain` rules via `options`. |
| `lookupKey(kind, normalized)`                             | Folds case for free-text kinds before hashing.                                                                                              |
| `maskIdentifier(kind, normalized)`                        | Display hint, e.g. `"+1 (604) •••-••12"`.                                                                                                   |
| `canonicalPhone(raw)` / `domainHostname(raw)`             | The default phone and domain rules.                                                                                                         |
| `sha256(value)`, `randomToken(bytes?)`, `safeEqual(a, b)` | Token helpers: hash high-entropy secrets, mint URL-safe tokens, compare in constant time.                                                   |

### Envelope format

| Bytes  | Field                          |
| ------ | ------------------------------ |
| 0      | format version (`0x01`)        |
| 1..2   | key version, uint16 big-endian |
| 3..14  | 96-bit random IV               |
| 15..30 | 128-bit GCM auth tag           |
| 31..   | ciphertext                     |

Overhead is 31 bytes per value.

## Limitations

Read these before relying on it:

- **It is not a key-management system.** Protecting, wrapping and distributing keys is your job (KMS, Vault, sealed
  secrets). If an attacker has your keys and your database, this does not help.
- **Lookup hashes leak equality.** Anyone with the database can see which rows share a value. They cannot reverse a
  hash without the HMAC key, but low-entropy values (birthdates, short usernames) are still guessable by someone who
  holds the key. Use a distinct `domain` per column and keep the HMAC keyring separate from the encryption keyring.
- **Random IVs and AES-GCM limits.** Each key should encrypt well under 2³² values. Rotate long before that.
- **No search beyond equality.** No prefix, range or fuzzy search on encrypted columns.
- **`canonicalPhone` is deliberately simple** (it assumes `+1` for 10-digit numbers). Pass a libphonenumber-based
  rule through `options.phone` for international data.
- **Node.js only** (`node:crypto`). Not for browsers or edge runtimes without Node compatibility.
- Not independently audited. It is a thin layer over standard primitives, and the tests cover tampering, AAD
  mismatches, rotation and key validation, but review it as you would any security code.
